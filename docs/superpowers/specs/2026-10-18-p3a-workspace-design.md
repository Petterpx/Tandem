# P3a 工作台主窗口 + 截图录屏 + 剪贴板 设计文档

依据总设计 `docs/superpowers/specs/2026-10-17-tandem-design.md`（下称"总设计"）§2、§3.4、§4、§4.0。本文件覆盖 P3a；与总设计冲突时以本文件为准，并已同步回总设计。

## 1. 目标与范围

日常调试在一个工作台窗口内完成：左侧选设备，中间投屏，右侧快捷操作与剪贴板，底部最近截图与操作记录；需要多台对照时把设备"弹出"为独立窗口。

P3 分三段，每段单独出计划、单独可用：

| 段 | 内容 |
|---|---|
| **P3a（本文件）** | 工作台外壳（设备列表 / 投屏 / 弹出）、截图、录屏、提示条、最近截图、操作记录、剪贴板标签、能力概览 |
| P3b | 快捷操作各分段：网络、应用管理、打开链接、开发者开关、系统设置、自定义命令 |
| P3c | 日志窗口、文件传输（拖入推送、⌘V 粘贴文件确认框、拖 APK 安装、文件浏览器） |

顺序：P1（已完成）→ **P3a** → P2（MCP）→ P3b → P3c → P4。

不在 P3a：右栏「AI」标签（随 P2）、快捷操作各分段（P3b）、⌘V 粘贴**文件**（P3c；⌘V 粘贴文本保持 P1 行为）。

## 2. 窗口

### 2.1 工作台（单例主窗口）

- App 启动时打开；点 Dock 图标或菜单栏「打开工作台」重新打开；关闭后 App 继续常驻菜单栏。
- **左栏 · 设备列表**：每行显示名称、USB / Wi-Fi、状态点；录屏中显示红点。断开的设备保留并置灰，回来后自动重连。右键菜单：「弹出为独立窗口」「停止投屏」「移除」（移除仅对已断开的设备可用）。底部「无线配对…」「设置」。
- **中间 · 投屏**：复用 P1 的画面与输入处理。上方显示设备名、系统 · 分辨率 · 连接方式、状态徽标、「弹出为独立窗口」；下方按钮行：返回 / 主页 / 多任务 | 截图 / 录屏。未选中设备时显示引导文案。
- **右栏**：标签「快捷操作 / 剪贴板」。P3a 的「快捷操作」只含能力概览（§6）。
- **底部**：左「最近截图」（§4.4），右「操作记录」（§5.3）。

### 2.2 弹出窗口

- 即 P1 的独立设备窗口，底栏新增截图 / 录屏按钮。
- 设备弹出后，工作台中间显示「已在独立窗口中显示」与「收回」（关闭该弹出窗口）；右栏仍作用于这台设备。
- 关闭弹出窗口即收回到工作台。同一台设备的画面同时只在一处显示。

### 2.3 菜单栏与设置

- 菜单栏：新增「打开工作台」；点设备 = 打开工作台并选中它（不再直接开独立窗口）。
- 设置「插上自动开窗」改为「插上自动显示」：打开工作台并选中新插上的设备。沿用原 UserDefaults 键。
- 设置新增截图目录、录屏目录，各带「选择…」。

## 3. 会话规则（选中过就保持）

`AppModel` 不再用"窗口开着"决定会话，改为维护**需要运行的设备集合** `wantedIDs = (工作台打开 ? keptIDs : ∅) ∪ poppedIDs`：

| 事件 | 结果 |
|---|---|
| 工作台中第一次选中设备 | 加入 `keptIDs`，启动会话 |
| 切换到其他设备 | 原设备仍在 `keptIDs`，会话继续 |
| 弹出 | 加入 `poppedIDs`（已在运行则不重启） |
| 关闭弹出窗口 | 移出 `poppedIDs`；若仍在 `keptIDs` 则会话继续 |
| 右键「停止投屏」 | 移出 `keptIDs`；若未弹出则停止会话。再次选中时重新启动 |
| 右键「移除」 | 移出两个集合，停止会话，从列表删除 |
| 关闭工作台窗口 | 停止所有未弹出设备的会话，`keptIDs` 保留；重新打开工作台时恢复这些会话 |
| 设备断开 / 回来 | 按 P1 的自动重连规则（1s / 2s / 5s 退避，最多 5 次） |

原 `openWindowIDs` 的位置由 `wantedIDs` 取代；自动重连、USB↔Wi-Fi 切换、退出时停止全部会话的逻辑不变。这些判断写成 `AppPolicy` 里的纯函数，可单测。

## 4. 截图与录屏

### 4.1 截图

- 入口：「截图」按钮或 ⌘⇧S（由 App 菜单命令处理，不下发到设备）。
- 走 `DeviceActions.screenshot()` → `adb exec-out screencap -p`，无损原分辨率，不需要投屏会话。
- 保存为 PNG，并把图片数据与文件 URL 同时写入 Mac 剪贴板。

### 4.2 录屏（固定画布）

- 入口：「录屏」按钮或 ⌘⇧R，再按一次停止。录制中按钮变红并显示时长，设备行显示红点。会话未运行时按钮不可用并提示原因。
- 录制内容来自投屏解码后的画面，不使用设备端 `screenrecord`，没有 3 分钟限制。
- **画布**：开始后以收到的第一帧尺寸确定画布，之后不变。每帧等比缩放、居中放入画布，空白处填黑色；设备旋转只改变画面在画布中的摆放。
- 编码：VideoToolbox 硬件 H.264，8 Mbps；帧时间沿用设备 PTS（相对首帧）；输出 mp4。
- 自动结束：设备断开、停止投屏、移除设备、退出 App 时保存已录部分，提示条注明原因（如"设备已断开，已保存已录制部分"）。退出时与停止会话一起在现有 4 秒期限内完成。
- 一帧都没收到：不生成文件，提示"未收到画面"。写入失败：提示错误并在操作记录标红。

### 4.3 文件与提示条

- 默认目录：截图 `~/Pictures/Tandem/`，录屏 `~/Movies/Tandem/`，目录不存在时创建。
- 文件名 `<设备名>_yyyyMMdd_HHmmss.<ext>`；设备名中的 `/`、`:` 替换为 `_`；同一秒重名时追加 `-2`、`-3`……
- 提示条显示在触发操作的窗口底部（工作台或弹出窗口），停留 8 秒，悬停时不消失；新提示直接替换旧提示。
  - 截图：缩略图、"已复制到剪贴板"、「在 Finder 中显示」。
  - 录屏：缩略图（首帧）、时长、大小、文件名、「拷贝」（文件 URL 写入剪贴板）、「在 Finder 中显示」（`NSWorkspace.activateFileViewerSelecting`）。

### 4.4 最近截图

- 本次运行内的截图与录屏，最新在左，最多 50 项，不持久化。
- 悬停显示「拷贝」「在 Finder 中显示」；可把文件拖到其他 App。
- 「清空」只清列表，不删文件。文件被外部删除后显示"文件已删除"，按钮不可用。

## 5. 架构

### 5.1 TandemCore

- **能力**：`Capability` 新增 `screenshot`、`record`。界面只根据能力集合决定按钮状态，不写平台判断。
- **`DeviceActions`**（DeviceCore 协议，AndroidDriver 实现）：每台设备一个，由 `DeviceManager` 按逻辑 id 提供；不依赖投屏会话；每次调用使用设备当前的 serial。P3a 仅 `screenshot() async throws -> Data`（PNG）；P3b 的操作加在这里。
- **帧多订阅**：`DeviceSession` 的单一帧回调改为可添加 / 移除多个订阅者（返回 token）；`VideoFrame` 增加 `presentationTime`（来自 scrcpy PTS）。投屏视图与录屏各自订阅，切到别的设备时录屏不受影响。
- **剪贴板推送**：scrcpy-server 一律以 `clipboard_autosync=true` 启动。设备推来的剪贴板消息：若有等待中的「读取」，作为其结果；否则以新事件 `SessionEvent.clipboardChanged(String)` 发出。
- **`MediaKit`**（新 target，与平台无关）：`CanvasRecorder`，输入 `VideoFrame`，负责画布布局、硬件编码、写 mp4，输出时长、尺寸、文件大小、首帧缩略图。画布布局计算为纯函数。P4 iOS 复用。

### 5.2 App

- **`ActionRunner`**（@MainActor）：所有面板操作经它执行——执行、写操作记录、失败时在面板显示错误信息与建议。来源 `.user` / `.ai`（P2 使用）。
- **`RecordingService`**：每台设备至多一个录制；订阅会话帧交给 `CanvasRecorder`；监听会话状态与停止 / 移除 / 退出以自动结束。
- **`CaptureStore`**：目录、命名、保存、最近截图列表、拷贝与在 Finder 中显示。
- **`ClipboardService`**：剪贴板标签的读写、历史、自动同步（§7）。
- **`WorkspaceView`** 及子视图：设备列表、投屏区、右栏标签、底部两栏、提示条。投屏视图从 `DeviceWindowView` 抽出共用。
- **配色**：集中在一个 Theme 文件，界面代码不直接写颜色值。

### 5.3 操作记录

- 字段：时间、来源（你 / AI）、设备名、描述、结果（成功 / 失败 + 原因）。
- 内存保存，最多 500 条，最新在上，可清空，不持久化。
- 只记录"操作"：截图、录屏开始 / 结束（含自动结束）、剪贴板读取 / 写入 / 写入并粘贴、自动同步开关。用户的触摸、滑动、按键不记录；自动同步的每次传输不单独记录。

## 6. 能力概览

「快捷操作」标签在 P3a 只列出当前设备每项能力及是否支持（✓ / —）。P3b 起在其上方加入各操作分段；不支持的分段整体置灰并标注原因。

## 7. 剪贴板标签

自上而下：

1. **预览区**：最近一次读取的内容，可滚动，上限沿用 256 KB。
2. **按钮**：「读取」（显示到预览区并复制到 Mac 剪贴板）、「写入」、「写入并粘贴」。
3. **输入框**（多行）：有文字时写入输入框内容，按钮显示「写入（输入框）」；为空时写入 Mac 剪贴板文本，显示「写入（Mac 剪贴板）」；Mac 剪贴板不是文本时按钮不可用并提示。
4. **历史**：每台设备最近 10 条，显示方向（读 / 写 / 同步）、时间、首行预览；每条可「再次写入」「复制到 Mac」。内存保存。
5. **双向自动同步**：每台设备单独开关，默认关闭，按设备 id 记在 UserDefaults。

自动同步：

- 设备 → Mac：收到 `clipboardChanged` 且该设备开关打开时写入 Mac 剪贴板；关闭时丢弃。
- Mac → 设备：任一设备开启同步时，每 0.5 秒检查 `NSPasteboard.changeCount`；有新文本则写入已开启同步的设备（不粘贴）。
- 防回环：每台设备记住最后一次同步的内容，相同则跳过；App 自身写 Mac 剪贴板（读取、截图复制、拷贝文件）时记录该 changeCount，不回传。

## 8. 视觉

浅色为主，参考 claude.ai 画布原型中的 Workspace 页面：侧栏冷灰、面板近白、投屏画布浅灰加淡点阵，单一强调色 #2F6FED；深色模式跟随系统派生。

## 9. 错误处理

- 所有操作错误统一为 `DeviceError`（信息 + 建议），由 `ActionRunner` 展示并记录为失败。
- 不支持的能力：按钮置灰，悬停显示原因。
- 设备断开：投屏区沿用 P1 的「已断开 / 重试」；录屏按 §4.2 自动保存。

## 10. 顺带处理的 P1 遗留

- App 宿主测试中不启动设备发现与会话（避免测试在手机上残留会话）。
- 自动重连 5 次用尽后，设备再次出现时重新获得自动重连。
- 设备列表触发的重连，在启动会话前再次确认该设备仍在 `wantedIDs` 中。

## 11. 测试

**单元测试**

- 文件命名：非法字符替换、同一秒重名递增。
- 最近截图：50 项上限、文件被删除后的状态。
- 操作记录：500 条上限、来源、失败记录。
- 剪贴板：历史 10 条上限、防回环判断、读取结果与自动推送的区分。
- 会话规则：§3 表中每一行。
- 画布布局：竖屏画布放入横屏画面时的缩放与居中；同尺寸时铺满。
- `CanvasRecorder`：用仓库内 `testsrc-64x48.h264` 解码后录制，中途换一次画面尺寸，校验输出 mp4 的时长与画布尺寸。

**真机集成测试**（设置 `TANDEM_TEST_SERIAL` 时运行）

- 截图返回 PNG，尺寸与设备分辨率一致。
- 录制 2 秒，生成的文件可被 AVFoundation 读取，时长约 2 秒。
- 开启自动同步时，设备端剪贴板变化推送到 Mac。

**人工验收清单**：多设备切换、弹出与收回、录屏中旋转、拖出缩略图、深色模式、关闭再打开工作台后会话恢复。
