# P2 ControlServer + MCP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 Claude Code 等 MCP 客户端经 `tandem-mcp` → `control.sock` → Tandem.app 操控设备（截图、UI 树、点按、滑动、输入、剪贴板），并加入 AI 自动启动会话、可视化、锁定开关与右栏「AI」标签。

**Architecture:** TandemCore 新增 `ControlProtocol`（JSON-RPC 消息、按行分帧、Unix socket）与 `MCPBridge`（CLI 的全部逻辑）；DeviceCore 新增坐标空间与 UI 树，AndroidDriver 用 `uiautomator dump` 实现 `DeviceActions.uiTree()`，MediaKit 新增截图缩放编码。App 新增 `App/AI/`：`AICommands`（执行层，经 `ActionRunner` 来源 `.ai`）、`ToolRegistry`（工具表、参数解析、能力过滤）、`ControlServer`（socket 服务），`MirrorSet` 增加 `ai` 集合实现自动启动与空闲停止。`tandem-mcp` 是 Xcode tool target，只有 `main.swift`，嵌入 `Tandem.app/Contents/MacOS/`。

**Tech Stack:** Swift 6（严格并发）、SwiftUI + AppKit、BSD socket（Darwin）、Foundation `XMLParser`、ImageIO / CoreImage、Swift Testing、XcodeGen。

**Spec:** `docs/superpowers/specs/2026-10-18-p2-mcp-design.md`（总设计：`docs/superpowers/specs/2026-10-17-tandem-design.md`）

## Global Constraints

- 最低系统 macOS 14；`SWIFT_VERSION: "6.0"`、严格并发；不引入第三方依赖。
- 测试一律用 Swift Testing（`import Testing`、`@Test`、`#expect`）。
- 新增或删除 App / AppTests / MCP 下的文件后先运行 `xcodegen generate`；`*.xcodeproj` 不提交。
- 包测试：`cd Packages/TandemCore && swift test`；App 测试：`xcodebuild test -project Tandem.xcodeproj -scheme Tandem -destination 'platform=macOS'`。
- adb 调用一律用 `DeviceInfo.serial`；会话、锁定、记录、缓存一律按逻辑 id `DeviceInfo.id` 索引。
- AI 的一切设备操作经 `AICommands` → `ActionRunner`（来源 `.ai`），不在 `ToolRegistry` / `ControlServer` 里直接调用会话或 adb。
- 颜色只从 `Theme` 取；注释用中文，密度与现有代码一致；提交信息用英文 conventional commits，不加署名行。
- 照抄 spec 的值：socket `~/Library/Application Support/Tandem/control.sock`（目录 0700、socket 0600）；坐标空间长边 1280；会话就绪等待 10 秒；AI 空闲 5 分钟停止；默认调用超时 30 秒；`wait_for` 默认 10 秒、最长 60 秒；`long_press` 默认 800ms；`swipe` / `scroll` 默认 300ms、约每 16ms 一次 move；`scroll` 距离 60%；CLI 重试间隔 0.5 秒、最多 15 秒；可视化提示 2 秒；拉起参数 `--background`。
- 新错误码：`INVALID_ARGUMENT`、`ELEMENT_NOT_FOUND`、`ELEMENT_AMBIGUOUS`、`APP_UNAVAILABLE`；错误结果文字 `CODE: 信息。建议：…`。
- 工作分支：`feat/p2-mcp`。

## Review Focus

1. **App 崩溃后残留的 socket 文件**：下次启动必须能正常监听；另一个仍在运行的 Tandem 占着 socket 时不能把它抢走。由 Task 2 的 `staleSocketIsReplaced`、`liveSocketIsNotStolen` 固定。
2. **对端已关闭时继续写 socket**（Claude Code 退出、App 退出）：默认会触发 SIGPIPE 直接杀掉进程，必须改为抛错。由 Task 2 的 `sendAfterPeerClosedThrows` 固定。
3. **中文 / emoji 文本的 UTF-8 字节被拆在两次 read 之间**：分行必须按字节处理，不能把半个字符解码成乱码或丢行。由 Task 1 的 `utf8SplitAcrossChunks` 固定。
4. **同一客户端并发调用**（一个 `wait_for` 等 10 秒时又来一个 `tap`）：`tap` 不被挡住，响应按 id 回到正确的请求。由 Task 3 的 `concurrentCallsResolveIndependently` 固定。
5. **AI 等待会话启动时会话失败或设备被移除**：要在 10 秒内返回会话的失败原因，不能挂起到客户端超时。由 Task 8 的 `sessionFailureIsReturnedWhileWaiting` 固定。

**Interfaces:**
- Consumes：Task 1、2 的全部类型。
- Produces:
  - `public struct BridgeOptions: Sendable` —— `connect: @Sendable () throws -> any LineChannel`、`launchApp: @Sendable () throws -> Void`、`launchTimeout: Duration = .seconds(15)`、`retryInterval: Duration = .milliseconds(500)`、`serverVersion: String`
  - `public actor MCPBridge { public init(client: any LineChannel, options: BridgeOptions); public func run() async }` —— `client.incoming` 结束时返回
  - `public final class StdioChannel: LineChannel { public init() }`（stdin 读行、stdout 写行）
  - `MCPBridge.supportedProtocolVersions = ["2024-11-05", "2025-03-26", "2025-06-18", "2025-11-25"]`，`fallbackProtocolVersion = "2025-06-18"`

**行为**（spec §2.1）：
- `initialize`：本地应答 `{protocolVersion, capabilities: {tools: {listChanged: true}}, serverInfo: {name: "tandem", version: serverVersion}}`。客户端请求的版本在支持列表里就原样返回，否则返回 fallback。记下 `clientInfo.name` / `version`。
- `ping` 应答 `{}`；客户端发来的通知（`notifications/initialized`、`notifications/cancelled` 等）忽略；其他未知方法返回 `RPCError.methodNotFound`。
- `tools/list`、`tools/call`：先确保与 App 的连接（`AppLink`），再用 bridge 自己的递增整数 id 转发，App 回复后换回客户端原来的 id（字符串 id 原样保留）。每个请求在独立 Task 中处理。
- 建立连接：`connect()` 失败时调用一次 `launchApp()`，之后每隔 `retryInterval` 重试 `connect()`，直到 `launchTimeout`。并发请求共用同一次尝试。连上后发送 `hello`（`protocolVersion: ControlProtocolVersion.current`，加上客户端名称和版本）；App 返回的版本不同就视为连接失败，失败原因是"Tandem 版本与 tandem-mcp 不一致"，建议"请重启 Tandem 与 MCP 客户端"。
- 连接失败：`tools/call` 返回 `ToolResult.failure(code: "APP_UNAVAILABLE", message: "无法连接 Tandem", suggestion: "请确认 Tandem 已安装且能正常打开")`；`tools/list` 返回 `RPCError(code: serverError, message: 同上)`。
- 连接中断：所有进行中的请求按上一条返回，连接置空，下次请求重新建立。不重放请求。
- App 发来 `tools/list_changed` 通知时，向客户端发送 `notifications/tools/list_changed`。

- Produces（都是 `async throws -> String`，返回给 AI 的一句结果）：
  - `enum TapTarget: Equatable { case point(x: Double, y: Double), index(Int), text(String) }`
  - `func tap(_ device: DeviceInfo, _ target: TapTarget) async throws -> String`
  - `func longPress(_ device: DeviceInfo, _ target: TapTarget, durationMs: Int) async throws -> String`
  - `func swipe(_ device: DeviceInfo, from: (x: Double, y: Double), to: (x: Double, y: Double), durationMs: Int) async throws -> String`
  - `enum ScrollDirection: String, CaseIterable { case up, down, left, right }`
  - `func scroll(_ device: DeviceInfo, _ direction: ScrollDirection, at: (x: Double, y: Double)?) async throws -> String`
  - `func typeText(_ device: DeviceInfo, _ text: String, submit: Bool) async throws -> String`
  - `func pressKey(_ device: DeviceInfo, _ key: DeviceKey) async throws -> String`
  - `static func deviceKey(named: String) -> DeviceKey?`：`back home recents enter delete tab up down left right volume_up volume_down power`
  - `func setClipboard(_ device: DeviceInfo, text: String, paste: Bool) async throws -> String`

**规则：**
- **顺序**：先 `touch`，再查锁定，再 `runningSession`，再换算坐标，最后执行。
- **锁定**：`runner.note(<title>, device:, source: .ai, failure: "设备已锁定，禁止 AI 操作")`，然后抛 `DeviceError(code: .AI_LOCKED, message: "设备已锁定，禁止 AI 操作", suggestion: "请在 Tandem 的「AI」标签中关闭「禁止 AI 操作」")`。
- **坐标空间**：取自 `sessionState(id)` 的 `.running(width, height)`。点坐标经 `space.normalized(x:y:)` 换算。
- **元素**：
  - `.index(n)`：从缓存取，取不到时抛 `ELEMENT_NOT_FOUND`，信息"没有序号为 n 的元素"，建议"请先调用 get_ui_tree"。
  - `.text(s)`：调用 `actions(id).uiTree()` 现读，再 `matching(text:)`。
    - 只有 1 个：点它的 `normalizedCenter`。
    - 多个：更新缓存，抛 `ELEMENT_AMBIGUOUS`，信息为"匹配到多个元素："加候选行，每行一个。
    - 没有：抛 `ELEMENT_NOT_FOUND`。
- **手势**（`session.send`）：
  - tap：down、up。
  - longPress：down，`sleep(durationMs)`，up。
  - swipe：down 在起点；`steps = max(1, durationMs / 16)`，第 i 步（1...steps）在线性插值 `i/steps` 处发 move，每步之间 `sleep(16ms)`；最后在终点 up。
  - scroll：中心点取 `at`（换算后），没有就用 (0.5, 0.5)。手指位移为 0.6 个屏幕边长，以中心点为中点：`down` 时手指从 `cy+0.3` 移到 `cy-0.3`，`up` 相反，`left` / `right` 用 x 轴同理（`right` 表示查看右侧内容，手指从 `cx+0.3` 移到 `cx-0.3`）。起点和终点都夹到 0…1，然后按 300ms 的 swipe 执行。
- **typeText**：全部是可打印 ASCII（0x20…0x7E）时 `send(.text(text))`；否则 `try session.setClipboard(text, paste: true)`，这样失败能报出来。`submit` 为真时再 `send(.key(.enter))`。
- **setClipboard**：调用 `clipboard.write(id, text:, paste:, session:)`。
- **记录**：操作类经 `runner.perform(title, device:, source: .ai)` 执行。title 如下：

  | 操作 | title |
  |---|---|
  | tap | `tap <元素文字或 desc>`，按坐标时 `tap (x,y)`（AI 坐标，取整） |
  | longPress | `long_press …`，格式同 tap |
  | swipe | `swipe (x1,y1)→(x2,y2)` |
  | scroll | `scroll down` 等 |
  | typeText | `输入文字（N 字）`，`submit` 时加 `并回车` |
  | pressKey | `press_key back` 等 |
  | setClipboard | `写入剪贴板` / `写入并粘贴` |

  title 里不出现输入内容和剪贴板内容。
- **可视化**：成功后 `presence.show(id, kind, label: title)`。tap 对应 `.tap(p)`；longPress 对应 `.longPress(p, seconds:)`；swipe / scroll 对应 `.swipe(from, to)`；typeText、pressKey、setClipboard 对应 `.label`（只显示顶部提示）。

**工具表**（spec §3.2、§3.4）：

- 每个工具 = 名称、中文描述、inputSchema（`type: object`、`properties`、`required`、`additionalProperties: false`）、所需 `Capability?`、执行闭包。
- 除 `list_devices` 外都有可选的 `device: string` 参数，描述为"设备 id、serial 或名称；只连接一台时可省略"。

- `tap` / `long_press` 的 `element` 参数在 schema 里写成 `{"type": ["integer", "string"]}`。
- `scroll.direction` 与 `press_key.key` 用 `enum`。

**参数规则：**
- `tap` / `long_press`：`x` 和 `y` 必须成对出现，与 `element` 二选一，否则 `INVALID_ARGUMENT`。
- `wait_for`：`text` 与 `id` 至少给一个；`timeout` 须在 (0, 60] 之间，单位秒，默认 10。
- `long_press.duration_ms`：须在 1…10000，默认 800。
- `swipe.duration_ms`：须在 1…5000，默认 300。

**执行：**
- 先 `commands.resolve(arguments["device"])`；工具有所需能力而设备不具备时，返回 `UNSUPPORTED`，信息"该设备不支持 <工具名>"。

- `list_devices` 结果为 `commands.listDevices()`，每台设备后追加一行 `  工具：<该设备可用的工具名，逗号分隔>`。

**过滤**：取 state 为 connected 的设备的能力并集，返回所需能力在并集中的工具，加上 `list_devices`；没有 connected 设备时返回全部工具。
